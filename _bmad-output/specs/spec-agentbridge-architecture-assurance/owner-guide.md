# Owner Guide — что происходит сейчас

## Сейчас

Мы **не пишем production-код**. Мы начинаем AA-1: определяем фундаментальные границы и правила архитектуры. Это похоже на проектирование несущей конструкции и пожарной безопасности до строительства здания.

Project Owner не обязан выбирать технические детали без объяснения. Перед каждым решением он получает короткую карточку:

1. что выбираем;
2. почему это важно;
3. последствия основных вариантов;
4. рекомендацию и её основания;
5. что остаётся неизвестным;
6. требуется ли решение Owner сейчас.

## Простой словарь

| Термин | Простое значение |
| --- | --- |
| Core | Общие обязательные правила, которые понимают все совместимые участники |
| Profile | Дополнительные правила для класса задач или отрасли |
| Binding | Как смысл протокола передаётся через конкретный транспорт/формат/механизм |
| Bridge | Необязательный перевод между AgentBridge и другой системой с явными потерями |
| Invariant | Правило, которое нельзя нарушать ни в одной реализации |
| Authority | Проверяемое право выполнить конкретное действие в конкретных пределах |
| Effect | Реальное изменение во внешней системе, а не просто полученное сообщение |
| Evidence | Проверяемое утверждение о ходе или результате с указанным источником |
| Conformance | Доказательство, что реализация выполняет обязательные правила спецификации |
| Fail-closed | При опасной неизвестности действие запрещается, а не предполагается безопасным |
| ADR | Короткая запись: какое архитектурное решение принято, почему и что отклонено |
| Gate | Контрольная точка, разрешающая только следующий ограниченный этап |

## Ближайшее осознанное решение

Следующее содержательное принятие Owner — пакет AA-1: архитектурные принципы, границы слоёв и scope первой baseline. До этого эксперты готовят и объясняют варианты; Owner не выбирает названия технологий вслепую.
